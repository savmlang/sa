# SaVM Mathematical Benchmark Suite & SaTest Developer Guide

This directory contains hardcore mathematical and SIMD compute benchmarks for **SaVM (Safe Abstract Virtual Machine)** along with equivalent cross-language benchmark implementations in **C**, **Go**, and **JavaScript (Node.js)** for performance comparisons.

---

## Benchmark Algorithms

| TestID | Benchmark Name | Mathematical Formulation / Algorithm | SaVM Features Tested |
|---|---|---|---|
| **#1** | **Cooley-Tukey FFT Butterfly** | Radix-2 Complex butterfly $Y_0 = x_0 + x_1 W$, $Y_1 = x_0 - x_1 W$, $W = e^{-i\pi/4}$, and complex vector energy norm $\|Y_0\|^2 + \|Y_1\|^2$. | `vmulf`, `vsubf`, `vaddf`, `vfma`, `vfop` (`sqrt`) |
| **#2** | **RK4 Lorenz Attractor Step** | 4th-order Runge-Kutta numerical integration of 3D non-linear chaotic dynamics: $\dot{x}=\sigma(y-x)$, $\dot{y}=x(\rho-z)-y$, $\dot{z}=xy-\beta z$. | High-order floating point pipeline, multi-stage arithmetic |
| **#3** | **Horner Orthogonal Polynomial** | Degree-7 polynomial $P(x) = \sum_{k=0}^7 c_k x^k$ evaluated at $x = 1.75$ using Horner'\''s method. | Hardware FMA (`vfma`), chained Horner pipelines |
| **#4** | **Mandelbrot Quadratic Map** | Complex quadratic map $z_{n+1} = z_n^2 + c$, checking magnitude $\|z_{n+1}\|^2 = z_r^2 + z_i^2$ for $c = -0.75 + 0.1i$. | Iterative floating point dynamics, `vmulf`, `vsubf`, `vaddf`, `vfma` |
| **#5** | **64-Bit Integer Avalanche & Hash** | Multi-round integer hash combining additions, Murmur/SplitMix64 multiplication, and XOR bitwise avalanche mixing. | `vadd`, `vbit` (XOR), `vmul` (64-bit integer SIMD) |
| **#6** | **2x2 Matrix Linear Transformation** | Matrix product $C = A \cdot B$ followed by vector linear transform $W = C \cdot V$ using FMA dot-products. | Fused matrix-vector transformations, `vmulf`, `vfma`, `mov` |

## Running the Benchmarks

### 1. SaVM (via SaTest)

Run the SaVM benchmark suite using the `SATEST_TEST_DIR` environment variable:

```powershell
# In PowerShell:
$env:SATEST_TEST_DIR="tests_benches"; cargo run -p satest --bin satest
```

```bash
# In Bash:
SATEST_TEST_DIR="tests_benches" cargo run -p satest --bin satest
```

`satest` automatically:
1. Parses `tests.build`
2. Invokes `sasm` to assemble `math/*.sasm` into `dist/*`
3. Validates register outputs against `expected/*.toml` for both interpreter and JIT tiers
4. Executes the benchmark iterations and reports latency distribution statistics (**Median**, **p75**, **p99**, and **Standard Deviation**).

### 2. C Benchmark (Clang / MSVC)

```powershell
# Using Clang:
clang -O3 tests_benches/c/main.c tests_benches/c/benchmarks.c -o tests_benches/c/bench_c.exe
.\tests_benches\c\bench_c.exe
```

### 3. Go Benchmark

```powershell
cd tests_benches/go
go run main.go benchmarks.go
```

### 4. JavaScript / Node.js Benchmark

```powershell
node tests_benches/js/main.js
```

## CTR (Control, Task & Runtime) Architecture & SaTest Authoring Guide

### 1. VMTaskState & Register Layout

Every execution thread in SaVM operates on an aligned 128-byte `VMTaskState` structure:
- **General-Purpose Registers (`r1` through `r8`)**:
  64 bytes total (each register is 64 bits), 64-byte cache-line aligned.
- **Scratchpad Pointer**: Provides access to 24 additional temporary 64-bit registers (192 bytes).
- **Largepad Pointer**: Dynamic heap buffer for tensor and matrix operations.
- **AME (Aggressive Matrix Extension)**: Tile registers for matrix acceleration.

### 2. The `tests.build` Configuration File

`tests.build` instructs `satest` on compilation, JIT flags, and benchmark iterations:

```text
; Compile source directory into dist directory
:compile math dist

; Enable JIT execution tests
:jit

; Enable performance benchmarking
:bench

; Set iteration count (B = billion, M = million, k = thousand, n = 1)
:iter 10 k
```

### 3. Writing `.sasm` Assembly Files

Every test imports the standard environment with `#import *`.

#### Immediate Loading (`reg`)
```sasm
; Load 64-bit integer
reg $r1::u8, 0::u8, 100::u64

; Load IEEE-754 double-precision float
reg $r2::u8, 0::u8, fp3.141592653589793::u64
```

#### Vector Floating-Point Operations (`vaddf`, `vsubf`, `vmulf`, `vdivf`)
```sasm
; Format: %u16[ 0::u4 | $src1::u4 | $src2::u4 | $target::u4 ], count::u32, off1, off2, offtgt
vmulf %u16[ 0::u4 | $r1::u4 | $r2::u4 | $r3::u4 ], 1::u32, 0::u32, 0::u32, 0::u32
vaddf %u16[ 0::u4 | $r3::u4 | $r4::u4 | $r5::u4 ], 1::u32, 0::u32, 0::u32, 0::u32
```

#### Fused Multiply-Add (`vfma`)
Single-rounding hardware FMA computing $target = (src1 \times src2) + src3$:
```sasm
; Format: %u16[ $src1::u4 | $src2::u4 | $src3::u4 | $target::u4 ], memflags::u8, count::u32, off1, off2, off3, offtgt
vfma %u16[ $r1::u4 | $r2::u4 | $r3::u4 | $r4::u4 ], 0::u8, 1::u32, 0::u32, 0::u32, 0::u32, 0::u32
```

#### Mathematical Functions (`vfop`)
Supports `sqrt`, `ceil`, `floor`, `trunc`, `nearest`:
```sasm
vfop %u16[ 0::u4 | $r1::u4 | $r2::u4 | $FOP_f64::u1 | $VFOP_SQRT::u3 ], 1::u32, 0::u32, 0::u32
```

#### 64-Bit Integer SIMD & Bitwise (`vadd`, `vsub`, `vmul`, `vbit`)
```sasm
; 64-bit integer addition
vadd %u32[ $u64::u4 | $r1::u4 | $r2::u4 | $r3::u4 | 0::u16 ], 1::u32, 0::u32, 0::u32, 0::u32

; Bitwise XOR
vbit %u16[ 0::u2 | $r3::u2 | 0::u4 | $r2::u4 | $r1::u4 ], %u8[ $VBIT_XOR::u4 | 0::u4 ], 1::u32, 0::u32, 0::u32, 0::u32
```
